# B/C 抓取差异与官方训练参数核查

2026-10-10。仅分析已有实际日志，没有重训、升级或重跑正式测试。

## 已完成的事实

相同 20 个全新 base0 种子，固定 drive_h5、15×4ms/action、4 次 diffusion、ensemble=1。B 官方成功 0/20；C 成功 9/20，其中 6/20 在首次成功后继续同一模型控制，2 秒每个物理 tick 均满足官方成功条件。官方条件为锅高度>0.82m、左右 TCP 各距随物体移动的抓取点<0.03m、锅上方向点积>0.8。连续官方成功不等同于全程双侧受力接触，物理接触另计；既有 hold contact 汇总包含起始 tick，有 2.004s 的边界计数，不应解释为超过预设保持窗口的改善。

B/C 使用相同训练超参数、各自从官方基础权重训练。C 同时改变示范数量、示范质量、严格60ms接口回放、真实稳定保持数据及训练统计，因此不是纯“数量”消融。B 原40轨迹保留，但原轨迹无精确历史时间戳；不能声称新旧数据时间质量完全一致。

## 失败来自哪里

按保存的遥测（通常每60ms及首次接触采样）统计，最佳同一时刻 max(左距离,右距离)：B 均值5.335cm、中位5.433cm；C 均值2.380cm、中位2.091cm。**这是 TCP 到物体抓取点距离，不是模型离线预测MAE。**

- B 20次：保存的遥测中均未发现两臂同时进入3cm。不能从60ms抽样断言4ms物理轨迹完全没有瞬时进入；官方成功则逐4ms检查。
- C 6次失败：保存的遥测中未双侧同时进入3cm。
- C 5次失败：有同时进入3cm的采样点，但这些点锅高度未超过0.82m，属于“对齐/接触却未完成有效抬升”。它们不是单纯初始定位失败，接触不代表形成稳定抓持。
- C 3次首次成功后保持失败：410006、410009、410012。
- C 6次成功并连续保持：410000、410002、410014、410017、410018、410024。

按每轨迹分阶段平均，再对20轨迹平均，TCP drive目标—实际误差（cm）：

|模型|左接触前|右接触前|左接触后|右接触后|
|---|---:|---:|---:|---:|
|B|0.445|0.677|2.865|5.552|
|C|0.137|0.164|2.882|0.791|

首次接触包含手指及机械臂，阶段定义见分析脚本；接触后平均混合成功/失败和不同时长，不能作纯因果估计。C右臂改善很大，左臂失败长尾仍明显。相同接口已经取得多次双臂真实成功，缺乏证据认为整体关节排列/坐标变换错误是主因；局部接触物理、预测目标不合适和drive状态无法反映接触偏差仍然可能并存。

410009 后续终态锅方向点积为负，左TCP跟踪在保持附近约5.76cm，支持接触后跟踪/翻转问题。410006 末端锅方向点积仍0.8356且保持期双侧接触持续，但连续官方条件失败，说明接触存在也不能保证全程几何阈值。410012 最接近首次保持失败的60ms样本左抓取距离3.003cm，夹爪命令约0.15，支持抓持几何余量不足的解释。前两例首次失效的精确4ms tick与附近60ms完整状态可能不同，不能确定每次失效首先违反哪一项；下一轮须在每个失效tick保存完整状态。

## 官方参数与本项目

核查当前 NVIDIA 官方 main 文档与源码（网页抓取日期2026-10-10；它们不是ALOHA Lift Pot专用最优参数保证），以及本机固定版本实际落盘配置。

|参数|B/C实际|官方默认/示例|判断|
|---|---|---|---|
|基础模型|GR00T-N1.7-3B|同|一致|
|学习率|1e-4|CLI 1e-4|一致，无证据须立即调低|
|学习范围|冻结LLM/visual，训练projector/action head|CLI同|一致|
|state dropout|0.2|CLI 0.2|一致；官方提示依赖本体状态任务可降低|
|权重衰减|1e-5|CLI 1e-5|一致|
|warmup|5% =100更新|CLI 5%|一致|
|精度/调度|bf16，cosine|当前本机official配置同|正常；load_bf16=false不是关闭训练bf16|
|更新次数|2000|入门示例2000；CLI默认10000|2000不属于明显错误；默认10000不是本任务保证更好|
|batch|micro/global 4 × accumulation4 =有效16|入门示例32，CLI默认64|偏小，值得受控研究；不是有效4|
|动作形式|关节relative、夹爪absolute|新embodiment示例同|一致；40步预测与示例16步不同，不代表不兼容|
|推理diffusion|4|官方open-loop默认4|一致|
|训练中验证|关闭|官方默认关闭，但建议open-loop/中间checkpoint趋势|默认不等于充分实验设计，应补验证|
|保存策略|500步，轮转仅1份，only_model|官方支持|节省空间但缺少中间模型比较与优化器恢复|
|分片|256，每epoch4shards|默认1024，100000shards；官方允许减少|需审计实际覆盖，不应把4shards误解成固定只学4条示范|

本机分片代码将每条轨迹全部有效anchor分入子序列，episode_sampling_rate=.1不等于永久丢掉90%观测；每个epoch重新生成4个shard随机计划。真实样本覆盖须增加seed/episode/frame计数器验证，不能从配置直接推断90条均等覆盖。

## 优先建议

1. **保留当前C作为有效基线，不先盲目延长训练。** 补同一验证集B/C离线关节、FK、夹爪误差；重点按接近、闭合、抬升、保持四阶段分层。现有一次forward仅证明能加载，不能证明验证误差已计算。
2. 对失败做小规模控制诊断，在独立开发种子上一次只改变h5→h1/h2，仍保持每动作60ms；检查双臂同步和接触后跟踪。qpos实验须独立训练语义，不能直接替换C drive输入。
3. 查夹爪闭合预测、预测目标TCP与实测TCP、relative反归一化及q01/q99端点裁剪。C统计重算导致高端夹爪范围变化，需离线比较真实标签与处理器实际编码，不能随意修改checkpoint统计来追成功率。
4. 补专家可成功的偏置接触、双侧闭合、失败恢复和稳定保持示范。既有新增50条已经含2秒保持，故“完全没有保持数据”不是正确解释；仍可能是覆盖和采样权重不足。模型失败轨迹须有可靠专家纠正标签才能监督加入。
5. 如果要训练参数消融，先固定C数据和统计，仅测试有效batch16→32（micro4,accum8，显存近似不因累计翻倍，但每更新计算增多），其他参数不变；同2000步样本曝光翻倍，需要同时报告样本预算，或做1000步有效32的曝光匹配对照。官方推荐更大batch是优化方向，不是已证明原因。
6. 第二个独立消融才考虑state_dropout .2→.1/0，保持其他配置；精细双臂任务可能获益，也可能过拟合，须验证。学习率1e-4先保留，5e-5只能作为后续独立实验，而非“官方要求”。
7. 新训练加入独立验证、按阶段离线误差和checkpoint选择。仅有save_only_model不能严格断点恢复优化器；从C权重训练是warm-start新实验，须记录优化器重新初始化。
8. 当前20种子现已用于失败分析，不能再称下一轮未调参盲测。开发集调参结束后锁定新的测试种子，固定策略比较，不按种子切换控制。

没有启动新训练。需要正式长训练时，仍按用户要求先报告时间、费用、空间和配置并等待确认。
